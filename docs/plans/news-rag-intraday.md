# 뉴스 근거 최신성: 당일 수집 제안

이 변경은 리뷰/승인을 위한 구현이며 운영 스케줄 변경 완료 보고가 아니다.
PoC #1466과 독립 PR. 크론 변경을 포함하므로 exact SHA 독립 GO와 본 건 명시 머지 승인 후 적용한다.

## 경로

- 기존 `/api/cron/news-rag-collect`는 KST 08:50/09:50에 **어제 기사**를 수집한다. 그대로 유지한다.
- 추가 `/api/cron/news-rag-collect?period=today`는 매시 00/30분에 **오늘 기사**만 수집한다. 자정 경계는 한 시점의 KST 날짜로 계산한다.
- 기존 임베딩 크론을 매시 05/20/35/50분으로 확대한다. 수집 함수에서 모델/임베딩 호출을 직접 이어붙이지 않는다.
- DM 뉴스클리핑 스케줄·생성·발송 코드는 변경하지 않는다. 9/3~9/9 소급 발송도 하지 않는다.
- 기존 CRON_SECRET 인증과 service-role 보호 유지. 잘못된 period는 400이며 수집/DB 쓰기 전에 거부한다.
- 기존 article_key 멱등 upsert, team_ids 원자 합집합, content_hash 임베딩 CAS를 재사용한다. DB migration/RPC 변경 없음.

## 수집 기록 해석

`genius_news_ingest_coverage` 키는 기존대로 **실행일 × 팀**이다. 각 행은 마지막 실행 스냅샷이며, 하루 누적 적재량이나 하루 전체 기사의 완전성을 뜻하지 않는다.
`detail`에 `period=today|yesterday;article_date=YYYY-MM-DD;snapshot=latest`를 성공/실패 모두 남긴다. 기본 호출과 당일 호출은 같은 실행일 칸을 갱신하므로 집계자는 반드시 이 범위를 함께 확인한다.
수집 실패, 적재 실패/시간 초과, 커버리지 기록 실패뿐 아니라 페이지 절단도 `ok=false`, HTTP 503이다. `truncatedTeams`로 잘린 팀을 구분한다. 0건 정상과 API 실패를 혼동하지 않는다.

## 예산·한계

- 수집: 하루 2회 → 50회(기존 2 + 당일 48). 팀당 최대 2페이지 × 10팀이므로 재시도 전 네이버 요청 상한은 하루 40 → 1,000회. HTTP 429 재시도는 별도이며 기존 공용 제한을 유지한다.
- 임베딩: 하루 24회 → 96회. 회당 최대 120건·동시성 2는 유지, 최대 처리 슬롯 2,880 → 11,520건/일. 빈 큐는 모델 호출이 없고, 스케줄이 실제 처리량/비용을 뜻하지 않는다. purge 호출도 24 → 96회다.
- 기사 검색 노출 후 일반적인 폴링 대기는 수집 최대 30분 + 임베딩 최대 15분이다. 처리시간·검색 공급자 반영 지연·실패·120건 초과 대기열은 추가되므로 **1시간 이내 보장이 아니다**.
- 뉴스 검색은 기존 10구단 질의이며 국제대회 전용 공식 일정/결과 소스는 추가하지 않는다. 구단 검색에 잡히지 않는 기사는 여전히 미수집일 수 있다.
- 당일 200건을 넘는 팀은 절단 신호가 날 수 있다. 이 PR은 증분 워터마크/깊은 백필을 구현하지 않는다.
- 위키 수집 정책/증분 갱신은 별도 미완료 항목이다.

## 독립 검증 및 롤백

삼식 실행: `npx tsx scripts/qa/news-rag-intraday.ts`, 기존 `baseball-news-rag-ingest-smoke.ts`, `news-clipping-delivery.ts`, 필수 CI.
