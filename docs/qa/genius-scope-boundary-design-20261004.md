## 다음 가설: 닫힌 범위 경계, 후보 하나

열린 접두 라벨은 제외 범위의 끝과 적용 본문의 끝을 표시하지 않는다. 닫힌 경계가 이를 보완하는지 검증한다. 원인 확정이 아닌 가설이며 라벨 단어 최적화·다중 후보 탐색은 하지 않는다. 기존 순수 파서·거절 범위·UTF-16 spans를 그대로 사용하고 renderer만 별도 실험 옵션으로 변경한다.
기호 E는 제외 접속사까지의 원문 span, G는 문장 끝까지 적용 본문 원문 span이다. E/G의 원문 공백·줄바꿈·순서는 그대로 보존한다.

```
<예외절 원문>E</예외절 원문><적용 본문 원문>G</적용 본문 원문>
```

접속사도 E에 포함한다. 네 태그만 제거하면 base 원문과 byte-identical. 별도 LF를 넣지 않는다. 원문에 같은 태그가 이미 존재하면 충돌로 원문 유지. 고정 추가량은 38 UTF-16 units/문장, 현 primary 최대6개로 +228/요청이다. 이 예산 변경은 설계 검토 대상이며 기존 +19/+114 상한 안에 든다고 주장하지 않는다. 물리7/선택6/형제1, nested sibling skip와 문맥/recordbook skip은 현 계약 유지. 추가 자료·긍정 규칙·보충 결론은 없다.
태그는 원문 구조 표지일 뿐 grounding 근거나 모델 지시가 아니다. 시스템/사용자 프롬프트 지침 추가, 원문 재서술, 제외 조건의 부정/역조건 생성, 질문 regex/allowlist, p60 pinning, 근거 삭제·순위 변경, DB 쓰기, 추가 모델 호출, 답변 사후 수정 금지.
