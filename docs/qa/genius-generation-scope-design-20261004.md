## 가설: 추가 지침이 아니라 생성 입력의 무손실 구문 분리

대상은 이미 선택된 공식 원문에 있는 완결된 선행 예외절이다. 질문·인필드 플라이·페이지 번호로 분기하지 않는다.
문장을 `예외 범위 원문`과 `그 범위 밖에 적용되는 본문 원문`의 두 span으로 분리해 같은 자료 안에서 표현한다.
`A를 제외하고 B`는 A에서 B를 주장할 수 없다는 경계일 뿐이다. A에서 B의 반대가 참이라고 생성하거나 저장하지 않는다.
인필드 플라이의 타자 아웃 결론은 별도로 검색된 긍정 조항에만 근거해야 한다. 긍정 근거가 없으면 구조 데이터가 답을 만들어 주지 않는다.

제안 데이터 계약:
- source identity: canonicalUrl, revision, sectionPath, rawContentSha256.
- relation: excludedScope(start,end), connective(start,end), governedClause(start,end), sentence(start,end), parserVersion.
- 모든 offset은 정규화 전 원문의 UTF-16 인덱스이며 half-open이다. 원문 slice 재결합이 원래 문장과 동일해야 한다.
- 렌더는 span 원문과 구분 라벨만 사용한다. 새 야구 사실·부정 반전·추론된 긍정 답·프롬프트 명령은 넣지 않는다.
- rawEvidence·guardEvidence는 그대로 두며 라벨·구조 필드는 grounding 근거가 아니다.

## 파서 경계와 적용 위치

1. 실제 서빙 원문에서 문장 경계가 온전히 있는 경우만 후보로 수집한다. 일반 구문 표지 `을/를 제외하고`의 선행 범위를 추출하되 의미가 불명확하면 무변경이다.
2. 중첩 예외·인용·열거 경계 걸침·앞뒤 절단·문장 경계 불명·다중 범위는 reject한다. PDF 공백 보정으로 없는 단어를 만들지 않는다.
3. 10개 이상 서로 다른 공식 조항을 판독표에 포함한다. 자동 수집 결과가 부족하면 HOLD이며 수기 항목으로 채우지 않는다. 성공·reject·미지원 표본을 모두 공개한다.
4. 렌더는 `official-parenthetical-evidence.ts`와 같은 원문 identity 경계에서 실험용 순수 함수로 분리한다. 합성된 sibling 문자열에서 다시 파싱하지 않고, 원래 자료별 span을 확인한 뒤 기존 bundle 조립 전에 변환한다.
5. 기존 괄호 제외 주석과 형제 블록은 보존한다. 선택 6개·물리 근거 상한 7개·형제 1개·현재 문맥/recordbook skip 계약은 바꾸지 않는다.
6. `buildRagLlmRequest`의 systemPrompt 동일성 판정을 깨지 않는다. 시스템 지침, 기준일, 문서 메타데이터, transport·timeout·응답 파싱·기존 가드는 base와 같아야 한다.
7. source/revision/hash/offset 불일치·렌더 예산 초과는 해당 변환을 생략하고 원문을 보존한다. 근거 삭제·답변 재작성·GENERAL 강제 이동은 없다.

## 기존 실패와 구별하는 통제

base는 현재 프로덕션 입력이다. 후보는 위 span 표현만 바꾼다. 새 주석을 기존 부기 뒤에 덧붙이는 방식은 후보가 아니다.
원문 보존 장부와 모델 표시 장부를 분리한다. 문장 text 재결합 동일성, 자료별 identity·순서·수·선택 서명 동일성을 요청 단위로 기록한다.
후보가 적용되지 않은 요청은 base payload와 byte-identical이어야 한다. 문맥·기준일·괄호 제외 블록 손실은 재생 전에 중단한다.
동일한 검색 스냅샷·extras·reference clock·모델 설정으로 base/후보를 쌍으로 재생하고, 실행 순서는 교차한다.
전송은 기존 production call 계약을 재사용한다. 현재 하네스에 아직 이 후보 옵션은 없다. 옵션·결속 smoke 구현 전 실행 명령이 준비됐다고 보고하지 않는다.

## R1 고정 렌더 예시·예산

변환 단위는 아래 p62의 완결 문장 한 개다. 청크 머리말·[부기]·뒤 [주1]과 그 절단 부분은 byte-identical로 둔다. base(줄바꿈·PDF 공백 그대로):

```
인필드 플라이 규칙이 적용되는 경우를 제외하고 내야수가 타구
에 닿지 않은 채 그대로 땅에 떨어뜨렸을 때는 타자는 아웃이 되 지 않는다.
```

후보(라벨 포함 정확한 문자열):

```
[예외절 원문]인필드 플라이 규칙이 적용되는 경우를 제외하고
[적용 본문 원문] 내야수가 타구
에 닿지 않은 채 그대로 땅에 떨어뜨렸을 때는 타자는 아웃이 되 지 않는다.
```

`excludedScope`는 조사 앞까지, `connective`는 조사부터 `제외하고` 끝까지다. 첫 라벨 뒤에는 두 span을 연속 출력하고, 둘째 라벨 뒤에는 원래 공백까지 포함한 governedClause를 출력한다. 라벨 둘과 추가 LF만 제거하면 base와 완전히 같다. `그 범위 밖`이라는 설명은 라벨에 넣지 않는다. source id 192183, rawContentSha256 `fb0bcfd2bd3308ac6dcd5f8d3af0d37e40922e668996b0e215841aabdbef9d00`.

고정 라벨은 `[예외절 원문]`, `[적용 본문 원문]` 두 개뿐이다. 문장당 증가 19 UTF-16 code units(라벨+LF), 문장 원문 상한 780 UTF-16 units, 청크당 최대 1문장·요청당 최대 7문장, 최대 증가 133 units. 초과는 원문 유지한다. 토큰 수와 문자 수를 혼동하지 않으며 실제 추가 토큰은 payload 계측에 기록한다. #1520처럼 원문 뒤 해석 주석을 중복 덧붙이지 않지만 라벨 자체의 프레이밍 위험은 남아 있어 독립 재생 전 효과를 주장하지 않는다.

## R1 읽기 전용 census (설계 수동 판독, 파서 실행 PASS 아님)

입력 `excl-serving-r1.jsonl`: 9,152행, SHA256 `06a277315dce24fdd7364b2a1b4cb1e008d500fe52918025b34d83f281f44e6f`. 이 스냅샷을 읽었으며 현재 DB census라는 주장은 하지 않는다. `제외하고` 포함 18개 청크/18회. `을/를 + 공백(개행 포함) + 제외하고`이며 뒤에 `는/도`가 없는 정확 표지는 14회, 변형/미지원 4회다. 정확 표지 14회는 중복 조항 2쌍을 제외하면 12개 서로 다른 조항/문장이다.

규칙 1·2 판독: 정확 표지 14회 중 통과 6회(서로 다른 조항 5개), reject 8회. 변형 4회는 미지원으로 원문 유지. 통과가 p62 한 건만은 아니지만 자동 파서 일반성은 아직 미검증이다. 10개 이상 판독 요구는 통과+reject의 서로 다른 원문 12개로 충족하며, 10개 자동 통과를 주장하지 않는다. 구현에서 이 census가 재현되지 않으면 HOLD다. 문장 경계는 해당 문장 기준이며 인접 문장의 절단은 분리해 보존한다. 종결 마침표 없는 개조식, 선행 주절이 있어 span 범위가 모호한 경우, 괄호 중첩, 외부 참조의 세부 의미를 추론해야 하는 경우는 원문 유지한다. 참조번호는 원문 span으로만 남기고 참조 내용을 확장하지 않는다.
