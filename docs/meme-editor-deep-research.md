## 1. 벤치마킹 리서치

### 1.1 밈 에디터 서비스 비교

#### imgflip (웹 밈 생성기 — 세계 1위)
- **핵심 UX:** 템플릿 선택 → 텍스트 입력 → 생성. 3스텝.
- **강점:** 100만+ 유저 업로드 템플릿, 드래그&리사이즈 텍스트, 커스텀 폰트/색상/테두리
- **약점:** 범용 밈, 커뮤니티와 분리, 모바일 UX 열악 (데스크톱 중심)
- **배울 점:** 밈체(Impact) 원탭 프리셋, 스티커/이미지 겹치기, "1,300+ 무료 폰트" 접근

#### Instagram Stories/Reels 에디터
- **핵심 UX:** 사진/영상 촬영 → 텍스트/스티커/드로잉/뮤직 오버레이 → 게시
- **강점:** 터치 인터랙션 최고 수준 (핀치줌, 회전, 스냅), 방대한 스티커/GIF(GIPHY 연동)
- **약점:** 스포츠 특화 없음, 템플릿 제한적
- **배울 점:** 터치 제스처 패턴 (2손가락 회전/확대), 텍스트 스타일 프리셋 UX, 하단 도구바 구조

#### CapCut (모바일 영상/이미지 편집)
- **핵심 UX:** 템플릿 기반 빠른 제작, AI 기능 (자동 자막, 배경 제거)
- **강점:** 성능 최적화 뛰어남 (모바일 네이티브), 트렌딩 밈 템플릿 자동 추천
- **약점:** 앱 설치 필요 (웹 아님), 커뮤니티 연동 없음
- **배울 점:** 트렌딩 템플릿 자동 추천, AI 텍스트 자동 배치, 모바일 성능 최적화

#### Canva
- **핵심 UX:** 범용 디자인 툴, 밈 템플릿 포함
- **강점:** 가장 많은 에셋/템플릿, 드래그&드롭, 다양한 내보내기 (이미지/GIF/영상)
- **약점:** 범용이라 무겁고, 밈에 특화 안 됨, 모바일 웹 UX 무거움
- **배울 점:** 레이어 시스템, 에셋 카테고리 분류, 템플릿 검색

#### 한국 짤생성기 앱들 (짤방생성기, 밈짤메이커 등)
- **핵심 UX:** 사진 위 텍스트 + 한국 밈 스티커
- **강점:** 한국 밈 문화에 맞는 폰트/스티커 (ㅋㅋㅋ, ㄷㄷ 등)
- **약점:** 기능 단순, UI 조악, 커뮤니티 없음
- **배울 점:** 한국 밈 폰트 (배달의민족 서체 등), 한국어 특화 텍스트 스티커

### 1.2 스포츠 앱 밈 생태계 분석

#### NBA/NFL/MLB 팬 밈 문화
- **Reddit (r/baseball, r/KBO):** 밈의 주요 생산/유통 채널. 외부 도구로 제작 → Reddit 업로드
- **Twitter/X:** GIF 반응 문화. "MJ crying", "Salt Bae" 등 범용 GIF + 선수 표정 GIF
- **디시인사이드 야갤:** 한국 야구 밈의 성지. 합필갤에서 제작 → 야갤 유통 → 타 커뮤니티 확산
- **MLB At Bat:** 경기 하이라이트 영상 클립 공유 기능 (밈 에디터는 없음)

#### 핵심 인사이트
> **밈 제작 도구를 내장한 스포츠 앱은 현재 존재하지 않음.**
> 이것이 기회. 크보팬이 최초가 될 수 있음.

야구 밈의 라이프사이클:
```
1. 소스 발생: 경기 중 명장면/웃긴 순간/선수 표정
2. 포착: 팬이 캡처 (TV 화면 캡처, 직관 사진, 중계 클립)
3. 가공: 외부 도구로 텍스트 추가 (포토샵/짤생성기/imgflip)
4. 유통: SNS/커뮤니티에 업로드
5. 2차 가공: 다른 팬이 변형/재생산
```

**크보팬의 기회:** 2~4단계를 앱 내에서 완결 → 밈 생산 속도 ↑ → 유통 자연스럽게 앱 내 + 외부 공유

### 1.3 벤치마킹 종합: 크보팬이 가져갈 것

| 서비스 | 가져갈 것 | 안 가져갈 것 |
|--------|----------|------------|
| imgflip | 밈체 프리셋, 1M+ 템플릿 개념, 드래그 텍스트 | 데스크톱 중심 UI, 범용 성격 |
| 인스타 | 터치 제스처, 스티커 UX, 하단 도구바 | 범용 스티커 (GIPHY), 무거운 에디터 |
| CapCut | AI 텍스트 배치, 트렌딩 템플릿 | 네이티브 앱 전제, 영상 중심 |
| Canva | 레이어 시스템, 에셋 분류 | 범용 디자인 도구의 복잡성 |
| 짤생성기 | 한국 밈 폰트/스티커 | 조악한 UI |

## 2. 기술 심층 비교

### 2.1 Canvas 라이브러리 비교: Fabric.js vs Konva.js

| 항목 | Fabric.js 7.0 | Konva.js |
|------|--------------|---------|
| **라이선스** | MIT ✅ | MIT ✅ |
| **GitHub Stars** | 30K+ | 12K+ |
| **번들 크기** | ~300KB (minified) | ~160KB (minified) |
| **React 바인딩** | 없음 (직접 통합) | react-konva (공식) ✅ |
| **TypeScript** | 네이티브 (v7에서 전면 재작성) ✅ | 지원 |
| **터치 제스처** | 기본 드래그 + 확장 필요 | 기본 드래그 + 확장 필요 |
| **텍스트 편집** | **캔버스 위 인라인 편집** (IME 지원) ✅ | 외부 textarea 필요 |
| **이미지 필터** | **WebGL + Canvas2D 필터** (20+ 내장) ✅ | 필터 지원 (Canvas2D) |
| **SVG 지원** | 강력 (SVG 파싱/렌더링) ✅ | 제한적 |
| **직렬화** | JSON 직렬화/역직렬화 ✅ | 제한적 |
| **성능** | 오브젝트 캐싱 시스템 ✅ | 레이어 기반 렌더링 ✅ |
| **클립 패스** | 강력 (임의 오브젝트로 마스킹) | 지원 |
| **애니메이션** | 내장 (tweening/easing) | 내장 (tweening) |
| **내보내기** | toDataURL, toBlob, toSVG | toDataURL, toBlob |
| **커뮤니티** | 활발 (Picsart 후원) | 활발 |
| **사용 사례** | Canva, Picsart, Postcard 등 | Miro 등 화이트보드 |

#### 추천: **Fabric.js** (승)

**이유:**
1. **텍스트 인라인 편집 + IME 지원** — 한국어 조합 입력이 Canvas 위에서 바로 됨. Konva는 외부 textarea 필요 → UX 열화
2. **WebGL 이미지 필터** — 팀 컬러 오버레이 같은 필터를 GPU 가속으로 실시간 미리보기
3. **JSON 직렬화** — 편집 중인 상태를 저장/복원 가능 (임시 저장, 돌아와서 편집 계속)
4. **SVG 파싱** — KBO 팀 로고 등 SVG 에셋을 그대로 사용 가능
5. **Canva/Picsart가 사용** — 프로덕션 검증된 라이브러리

**Konva의 장점(react-konva)은 wrapper로 해결 가능.** React 내에서 Fabric.js를 useRef로 관리하는 패턴이 일반적.

### 2.2 GIF 생성 기술 비교

#### Option A: gif.js (클라이언트, MIT 라이선스)
```
장점:
- 순수 JavaScript, 서버 불필요
- Web Workers로 백그라운드 인코딩 (메인 스레드 블로킹 없음)
- Canvas 프레임을 직접 추가 가능 (밈 에디터와 자연스러운 연동)
- ~30KB 번들

단점:
- 동영상을 프레임으로 분해하는 기능 없음 (별도 디코딩 필요)
- GIF 인코딩 품질이 FFmpeg보다 낮음
- 대규모 GIF(10초+) 시 메모리 이슈 가능

적합한 경우:
→ "사진 여러 장 → 슬라이드쇼 GIF" 같은 간단한 경우
→ Canvas에서 애니메이션을 녹화하여 GIF로 만드는 경우
```

#### Option B: FFmpeg.wasm (클라이언트, LGPL 2.1 + MIT)
```
장점:
- FFmpeg의 전체 기능을 브라우저에서 사용
- 동영상 → GIF 직접 변환 가능 (디코딩 + 인코딩 한방)
- 높은 품질 (palettegen/paletteuse로 256색 최적화)
- LGPL이지만 WASM은 동적 링크로 간주 → 상업 사용 OK

단점:
- 번들 크기 ~25MB (WASM 코어 다운로드 필요)
- 모바일 메모리 제약: 10초 480p 동영상 변환 시 ~200MB RAM
  - iPhone 12 이하: 메모리 경고 가능
  - 최신 기기 (iPhone 14+, 갤럭시 S23+): 무난
- SharedArrayBuffer 필요 → COOP/COEP 헤더 설정 필수
  - Next.js + Vercel에서 설정 가능하지만 주의 필요
- 첫 로딩 시 WASM 다운로드 시간 (CDN 캐시로 완화)

적합한 경우:
→ "동영상 클립 → GIF" 변환이 핵심인 경우
→ 서버 비용을 아끼고 싶은 경우
```

#### Option C: 서버 사이드 FFmpeg (Supabase Edge Function / Vercel)
```
장점:
- 모바일 기기 성능과 무관하게 안정적
- 번들 크기 영향 없음
- 품질 최고 (서버 FFmpeg는 제한 없음)

단점:
- 업로드 시간 (동영상 파일 크기에 비례)
- 서버 비용 (Vercel: 10초 제한 / Supabase: Edge Function CPU 제한)
- 네트워크 의존적

적합한 경우:
→ 저사양 기기까지 지원해야 하는 경우
→ 높은 품질이 필수인 경우
```

#### Option D: WebCodecs API + gif.js (하이브리드)
```
장점:
- WebCodecs로 동영상 디코딩 (하드웨어 가속, 매우 빠름)
- 디코딩된 프레임을 gif.js로 인코딩
- FFmpeg.wasm보다 메모리 효율적 (스트리밍 디코딩)

단점:
- Safari 16.4+에서만 지원 (iOS 16.4+, 2023.3 출시)
  → 2026년 기준 대부분 기기 지원 ✅
- 구현 복잡도 높음

적합한 경우:
→ 최적의 성능과 품질의 균형
→ 최신 브라우저 타겟 (PWA라 OK)
```

#### 🏆 추천 전략: **Phase별 점진적 접근**

```
Phase 2 (개막 전, MVP):
  → 밈 에디터만 (사진 + 텍스트/스티커)
  → GIF 없이도 밈 생산 가능

Phase 3-A (4월, GIF v1):
  → FFmpeg.wasm 기반 (클라이언트 변환)
  → 제한: 최대 5초, 360px, 10fps
  → 저사양 기기 대응: "기기 성능이 부족합니다" 안내 + 서버 폴백 옵션

Phase 3-B (5월, GIF v2):
  → WebCodecs + gif.js로 마이그레이션 (성능 개선)
  → 또는 서버 하이브리드 (미리보기 클라이언트, 최종 변환 서버)
  → 제한 확대: 10초, 480px
```

## 3. UX 설계 (리서치 기반 업그레이드)

### 3.1 게시물 작성 플로우 — "스마트 3스텝"

imgflip의 "3스텝 완료" + 인스타의 "터치 최적화"를 결합:

```
[FAB ✏️]
   ↓
┌─ Step 1: 미디어 ─────────────────────┐
│                                       │
│  📸 사진  |  🎬 GIF 만들기            │ ← 탭 전환
│                                       │
│  [사진 선택 그리드]                    │
│  최대 10장, 드래그로 순서 변경          │
│                                       │
│                        [다음 →]       │
└───────────────────────────────────────┘
   ↓
┌─ Step 2: 편집 (선택적) ──────────────┐
│                                       │
│  [사진 풀스크린 미리보기]              │
│                                       │
│  도구바:                               │
│  [📝텍스트] [😄스티커] [🎨필터]       │
│  [📐밈템플릿]                         │
│                                       │
│  ← 스킵 가능 (단순 사진이면 바로 다음) │
│                        [다음 →]       │
└───────────────────────────────────────┘
   ↓
┌─ Step 3: 정보 (한 화면) ─────────────┐
│                                       │
│  📷 사진 3장 미리보기 (수평 스크롤)    │
│                                       │
│  ⚾ 경기 연결 ── [삼성 vs 한화 ✓] ──  │ ← 자동 추천, 원탭
│                                       │
│  👤 선수 태그 ── [구자욱] [+] ────── │ ← 경기 기반 추천
│                                       │
│  ✏️ ────────────────────────────────  │ ← 한마디 입력
│                                       │
│  #️⃣ [#직관] [#삼성라이온즈] [+] ────  │ ← 자동 생성
│                                       │
│                     [게시하기 🔥]      │
└───────────────────────────────────────┘
```

**핵심 UX 원칙:**
1. **Step 2는 스킵 가능** — 편집 안 하는 유저는 Step 1 → Step 3 직행
2. **Step 3은 한 화면** — 스크롤 없이 모든 입력이 보여야 함 (인스타 방식)
3. **자동 추천이 80%** — 유저가 직접 입력하는 건 "한마디"뿐

### 3.2 경기 태깅 UX — "Zero Friction"

벤치마킹에서 배운 핵심: **입력을 최소화하는 게 최고의 UX**

```
자동 추천 로직 (우선순위):
1. GPS → 구장 반경 1km 이내 → 해당 경기 자동 선택 (확인만)
2. 시간대 → 경기 종료 후 3시간 이내 → 해당 경기 최상단
3. 내 팀 → 유저 프로필의 "지정팀" 경기 우선
4. 복수 경기 → 카드 UI로 원탭 선택
```

```
┌──────────────────────────────┐
│  ⚾ 경기 연결                 │
│                              │
│  ┌────────────────────────┐  │
│  │ ✓ 삼성 5:3 한화         │  │ ← 자동 선택됨 (GPS/시간)
│  │   3/6 · 대전 · 2시간 전  │  │    체크 해제로 연결 해제
│  └────────────────────────┘  │
│                              │
│  다른 경기 선택 ▼             │ ← 접힘 (보통 안 열어도 됨)
```

### 3.3 밈 에디터 UX — "인스타 급 터치 + KBO 에셋"

### 4.2 GIF 파이프라인

```
Phase 3-A (FFmpeg.wasm):

VideoInput (File/Blob)
    ↓
FFmpegWasm.load() ← CDN에서 25MB WASM 로드 (캐시됨)
    ↓
FFmpegWasm.exec([
  '-ss', startSec,
  '-t', duration,
  '-i', 'input.mp4',
  '-vf', 'fps=10,scale=360:-1:flags=lanczos,split[s0][s1];[s0]palettegen[p];[s1][p]paletteuse',
  'output.gif'
])
    ↓
Blob → MemeEditor에 전달 (Fabric.js backgroundImage로)
    ↓
텍스트/스티커 추가 후 → 최종 GIF 내보내기
    ↓
Supabase Storage에 업로드


Phase 3-B (WebCodecs + gif.js):

VideoInput
    ↓
VideoDecoder (WebCodecs API, HW 가속)
    ↓
프레임 스트림 (VideoFrame[])
    ↓
각 프레임에 Fabric.js 오버레이 합성 (Canvas)
    ↓
gif.js에 프레임 추가 (Web Worker 인코딩)
    ↓
최종 GIF Blob → 업로드
```

## 8. 핵심 결론

### 기술적 실현 가능성

> **밈 에디터: 완전히 가능.** Fabric.js(MIT)로 인스타 스토리 급 편집 UX를 웹에서 구현 가능. Canva/Picsart가 동일 기술 스택 사용중.
>
> **GIF 생성: 가능하되, 제한 필요.** FFmpeg.wasm으로 클라이언트 변환 가능. 최대 10초/480px 제한 + 저사양 기기 폴백. 서버 비용 ₩0.

### 전략적 포지셔닝

> **"밈 제작 도구를 내장한 스포츠 앱은 현재 존재하지 않음"**
>
> 이 블루오션을 크보팬이 최초로 점유하면:
> 1. 밈 생산 → 앱 내 유통 → 외부 공유 시 워터마크 바이럴
> 2. KBO 전용 에셋이 경쟁 우위 (다른 앱에서 대체 불가)
> 3. 경기/선수 태깅 + 밈 = 콘텐츠에 구조화된 메타데이터 자동 부여

### 비용

> 라이브러리 비용: **₩0** (모두 MIT/LGPL 오픈소스)
> 서버 비용: **₩0** (클라이언트 변환)
