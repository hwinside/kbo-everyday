## 1. 문제·가치

선수 프로필의 스탯이 **시즌 누적 + 라이브 스플릿**에 머물러, 팬이 바로 이해하는 두 축이 비어 있음:
- **시간 축** — "요즘 잘 치나?" (추이) / "그 경기 어땠나?" (경기별 로그)
- **상황 축** — 투수 스플릿이 타자 기준 지표(OPS)로 표기돼 부정확

V1은 이 둘을 *데이터 토대(game_logs) 한 번 깔고* 그 위에 추이·경기별·스플릿을 얹는 수직 슬라이스.

## 2. 범위

### V1 (이번)
1. **game_logs 적재** — 경기 종료마다 선수별 경기 스탯 라인 영속화 (모든 후속 기능의 토대)
2. **선수 경기별 탭** — 스샷처럼 (최근 10경기 + 더보기 전체)
3. **추이: 월별 → 주간** — 타자 주간 타율 / 투수 주간 ERA
4. **타자 스플릿** — 화면 그대로 (단 홈/원정 행은 V1.5로 범위 지연 — 소스 부재 아님)
5. **투수 스플릿** — OPS→**피안타율**, 홈런→**삼진(K)**, `vs좌타 / vs우타 / 2아웃`

### V1.5 (B-① — V1 다음 묶음)
- **홈/원정 스플릿** (타자·투수 **둘 다**) — KBO 상황표엔 홈/원정 표가 없지만 `game_logs.is_home`으로 *보조소스 없이 파생 가능* (삼순 리뷰 #3). 범위상 V1.5로 지연일 뿐 소스 막힘 아님
- **투수 득점권(RISP)** — 득점권은 여러 주자상황 행의 *가중 집계*가 필요한데, KBO 투수 상황표엔 행별 실제 AB(분모)가 없어 집계 불가. **이것만 진짜 보조소스 필요**

> B(홈/원정 + 투수 RISP)는 하린아빠 결정대로 V1 다음에 한 번에. 단 막힌 이유는 다름 — 홈/원정은 game_logs로 풀리고, 투수 RISP만 외부 소스 의존.

### 비범위 (V1/V1.5 모두 아님)
- 수비 지표 / 멀티시즌·커리어 / 세이버(FIP·wRC+·WAR) 영속화

## 4. 데이터 모델

신규 테이블 `player_game_logs` (경기당 선수 1행):

```
player_game_logs
  id              bigint PK
  kbo_id          text        -- 선수 단독키
  player_type     text        -- 'batter' | 'pitcher'
  game_id         text        -- KBO/네이버 gameId
  game_date       date
  team_code       text        -- ★경기 당시★ 소속팀 (이적 대비 — 결과·팀 기준 집계용)
  opponent_team   text        -- 상대 팀 코드
  is_home         boolean     -- 적재해 두면 V1.5 홈/원정 split을 보조소스 없이 파생
  result          text        -- 'W' | 'L' | 'D' (경기 당시 소속팀 기준)
  -- 타자
  ab int, h int, hr int, rbi int, bb int, so int
  -- 투수 (★IP는 thirds라 정수 아웃으로 저장★ — 5.1이닝 = 16아웃)
  ip_outs int, er int, h_allowed int, k int, bb_allowed int
  created_at, updated_at
  UNIQUE (kbo_id, player_type, game_id)   -- 멱등 upsert
```

> ⚠️ **IP는 절대 `numeric`으로 저장·합산 금지** (삼순 리뷰 #1). KBO `5.1`은 5.1이 아니라 5⅓.
> - 저장: `ip_outs`(총 아웃 정수). 5.1이닝 → 16, 6이닝 → 18
> - 표시용 IP = `floor(ip_outs/3)`.`(ip_outs%3)` (예: 16 → `5.1`)
> - 주간/시즌 ERA = `ΣER × 9 / (Σip_outs / 3)`. decimal IP 합산 시 ERA 어긋남

- 시즌 누적 타율/ERA(스샷의 AVG·ERA 열)는 game_logs 러닝 합산으로 계산 (별도 저장 불필요).
- 적재: 경기 종료(boxscore 확정) 트리거 → 네이버 record 파싱 → 출전 선수별 upsert. 기존 박스스코어 fetch 재사용.

## 5. 화면 스펙

### 5-1. 경기별 탭 (스샷 기준)
- **타자**: 최근 10경기 결과 스트립(승=초록 W / 패=H 빨강 박스) + 표 `날짜 · 상대 · 결과 · AB · H · HR · 타점 · AVG(시즌누적)`
- **투수**: 같은 틀, 컬럼만 `날짜 · 상대 · 결과 · IP · H · ER · K · BB · ERA(시즌누적)`
- 기본 최근 10경기, **더보기**로 시즌 전체

### 5-2. 추이 (월별 → 주간)
- 타자 = 주간 타율(주 H/AB), 투수 = 주간 ERA(주 ER/IP×9)
- TrendChart 데이터를 mock → game_logs 주 단위 집계로 교체

### 5-3. 스플릿
- **타자**: 화면 그대로 (좌투/우투·득점권·2아웃·만루). 홈/원정 행은 V1.5까지 숨김
- **투수**: `vs좌타 / vs우타 / 2아웃`, 지표 = **피안타율** + **삼진(K)** (OPS·홈런 자리 교체)

## 6. 빌드 순서 (수직 슬라이스)

1. `player_game_logs` 테이블 + 적재 (경기 종료 트리거, 멱등 upsert) + 백필 스크립트
2. 선수 경기별 탭 (타자/투수)
3. 주간 추이 (TrendChart 실데이터 교체)
4. 투수 스플릿 정비 (피안타율 + K)
5. (V1.5) 홈/원정 = `game_logs.is_home` 파생 + 투수 RISP = 보조소스 연동

> 각 단계 End-User QA 통과 후 다음. game_logs가 토대라 1번이 선행 필수.
