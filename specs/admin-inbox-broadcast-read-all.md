# 어드민 쪽지함: 단체발송 숨김 · 모두 읽음

요청: 2026-09-09 #cs `1788917233.098669`.

## 범위
- 운영팀 수신함 목록에서 단체발송 사본을 제외한다. 접힘/그룹화하지 않는다.
- 기존 개별 대화는 마지막 개별 메시지 시각/미리보기로 정렬한다. 단체발송 뒤 들어온 사용자 답장은 정상 노출한다.
- 단체발송은 큐 발송의 서버 전용 `dedup_key=admin-broadcast:...`로 식별한다. 본문 유사도로 판단하지 않는다.
- 건의함 회신, 사진 쪽지, 탈퇴 사용자 대화는 기존 노출 계약을 유지한다.
- 사용자 쪽지함과 대화 원문, 공유 미리보기, 발송함 집계, 발송 큐에는 변경하지 않는다.
- 모두 읽음은 현재 페이지와 무관하게 운영팀이 받은 전체 안읽은 메시지에 적용한다. 운영팀이 보낸 쪽지의 사용자 읽음 여부와 일반 사용자 간 대화는 변경하지 않는다.
- 처리 SQL 스냅샷 이후 도착한 쪽지는 안읽음으로 남는다. 중복 처리는 멱등이다.
- 모두 읽음은 실행 전 확인창에서 검색·페이지와 무관한 전체 수신 범위와 되돌릴 수 없음을 안내한다. 취소하면 요청·로딩·카운트 변경 없이 종료한다.

## 구현 / 배포 순서
1. `20260909110000_admin_inbox_broadcast_read_all.sql` 적용: 관리자 목록 RPC 교체, 부분 인덱스, service_role 전용 전체 읽음 RPC.
2. API/UI 배포. API의 기존 관리자 인증을 통과해야 하며 운영팀 ID는 서버 설정에서만 가져온다.
3. 처리 후 목록과 사이드바 카운트를 재조회한다. 오류는 성공으로 표시하지 않는다.

## PR #1403 운영 QA 후속 (2026-09-09)
- 삼식 판정 원문: https://app.slack.com/archives/C0AKRDUGC2U/p1788922122545219 (배포 `5522a5b61eaf9db463e2b3a4ead08eb412cf7cea`). 목록·대화 보존·신규 UI·권한 검증 PASS 보고. 운영 전체 읽음 실클릭은 기존 미읽음 데이터를 보존하기 위해 미실행이며, 완료로 간주하지 않는다.
- P2 구버전 오버로드: `20260909120000_admin_inbox_drop_legacy_overload.sql`은 운영 백업으로 확인한 `(UUID, INT, TIMESTAMPTZ, UUID)` 시그니처만 삭제한다. 현재 라우트가 쓰는 `(UUID, TIMESTAMPTZ, UUID, INT)` 및 service_role ACL·쪽지 데이터는 보존한다.
- 적용 전 `pg_get_functiondef`·ACL로 구버전 정의를 백업하고 시그니처를 재확인한다. `DROP ... IF EXISTS`로 신규 DB/재실행에 안전하며, CASCADE 없이 예상 밖 의존성이 있으면 트랜잭션을 실패시킨다. PostgREST 스키마 캐시는 커밋 후 갱신한다.
- 배포 후 service_role의 2개/4개 이름 인자 목록 호출을 검증한다. 확인창 취소는 운영 데이터 변경 없이 QA 가능하며, 확인 후 성공·실패/재시도는 격리 테스트 데이터로 검증한다. 실데이터 전체 읽음을 QA 목적으로 실행하지 않는다.
- 후속 롤백: UI 확인창만 revert 가능. 구버전 함수 복구가 꼭 필요하면 사전 백업 정의·ACL만 복원하고 스키마 캐시를 갱신한다(2인자 모호성이 재발하므로 정상 롤백 경로는 아님). 메시지 데이터 롤백은 불필요하다.
