# 직관 다이어리 v1 — Spec

> 상태: 구현 중. 2026-07-21 하린아빠가 `자동 기록형 v1`을 선택하고
> “최애선수 활약이 평균 대비 어떤지도 함께” 추가 요청.
> 선행 기능: [[venue-stories]] — 지오펜스 검증을 통과한 직관 스토리.

## 목표

직관 스토리 업로드를 별도 입력 없이 영구 직관 인증으로 전환한다. 스토리 미디어가
경기 종료 후 삭제되어도 직관 경기·결과·승률은 남는다. 각 경기에서는 현재 최애선수 중
해당 경기에 참가한 팀 소속 선수의 경기 기록을 **그 경기 이전 시즌 경기당 평균**과 비교한다.

## v1 범위

- 첫 직관 스토리 생성 시 `(user_id, game_id)` 기준 영구 직관 기록 1건을 멱등 생성
- 관리자 GPS 우회 업로드는 `admin_qa`로 분리하고 실제 직관 기록·승률에서 제외
- 직관 인증 시점의 응원팀이 해당 경기 참가팀이면 `support_team_id`로 스냅샷
- 조회 시 KBO 공식 경기 상태·최종 스코어를 결합하고, 조회 실패 상태는 집계에서 제외
- `/my`에 시즌 직관수·승/패/무·승률 요약 카드
- `/my` 카드 안에 인증 직관 경기 최신순 목록과 경기별 최애선수 상세 펼침
- 취소·예정·진행 경기는 승률 분모에서 제외(실제 구장 방문 수에는 포함)
- 응원팀이 참가하지 않은 중립 경기는 직관수에는 포함하되 승패 집계에서 제외
- 최애선수는 현재 프로필의 최대 5명 중 해당 경기 참가팀 소속만 표시
  - 타자: 타수·안타·홈런·타점을 해당 경기 전 경기당 평균과 비교
  - 투수: 이닝·자책·탈삼진을 해당 경기 전 경기당 평균과 비교
  - 평가는 위 기록을 함께 반영한 활약 지수로 `평균 이상/비슷/아쉬움` 표시
  - 비교 표본은 해당 경기 전 출전 3경기 이상일 때만 `평균 이상/비슷/아쉬움` 평가
  - 팀은 참가했지만 로그가 없으면 `미출전`, 데이터 적재 전이면 `기록 집계 중`

## v1 제외

- 과거 경기 수동 추가
- 메모 편집·다이어리 전용 사진 영구 보관
- 상대팀별 승률 분석
- 과거 시점의 최애선수 목록 스냅샷

## 데이터 모델

`venue_attendance`

- `user_id`, `game_id` unique — 한 유저의 한 경기 직관은 1건
- 경기 날짜·구장과 인증 당시 응원팀 스냅샷
- `source='story_geofence'`, `recorded_at`
- 클라이언트 직접 접근 없음. RLS 활성화 + API의 service role만 사용
- 본인 전용이며 공개 프로필에는 노출하지 않음

## API

- `GET /api/me/venue-attendance?season=` — 본인 인증 필수
  - 시즌 요약과 경기별 공식 결과 반환
  - 현재 최애선수의 경기 이전 평균 대비 활약 반환

## 보안·무결성

- 직관 기록 생성 권한은 기존 스토리 POST의 서버 지오펜스·미디어 검증 뒤에서만 발생
- 사용자 제공 user/team/score 값은 받지 않고 서버 경기·프로필 데이터만 사용
- `(user_id, game_id)` unique + trigger `ON CONFLICT DO NOTHING`으로 동시 업로드 중복 방지
- 관리자 GPS 우회 업로드는 `admin_qa`로 분리하고 attendance trigger에서 제외
- 스토리 삭제·만료와 직관 기록 삭제를 연결하지 않음
- 스토리 미디어 URL·썸네일·캡션을 직관 기록에 복제하지 않음
- 신규 마이그레이션은 PR 리뷰 전에 프로덕션에 적용하지 않음

## Definition of Done

- 자동 기록 멱등성·응원팀 스냅샷·취소/중립 집계 회귀 테스트
- 타자/투수 평균 대비 방향·미출전·데이터 대기 회귀 테스트
- 기존 직관 스토리 QA 전부 통과
- TypeScript·ESLint 신규 오류 0
- 실제 로그인 유저 기준 `/my → 직관 다이어리` 동선과 인증 기록 노출 확인
